### 2-4. 장면 구성 편향 발견과 수정

분리 실험 40회를 `mix3_stats.py` 로 봤더니 같은 과일 여러 개 장면이 목표보다 적었다.

|---|---|---|
| 같은 과일 2~4개 | 30% | 45~55% |
| 그중 4개 | 2% | 12~18% |

원인은 `gen_scripted.py` 의 배치 다시 뽑기 루프다. 다시 뽑을 때마다 `sample_layout()` 을 새로 불러 **장면 종류와 과일 개수까지 새로 뽑는다.**
- 여러 개 장면은 자리 조건에 더 자주 걸린다(가장 가까운 것과 둘째의 거리 차 2.5cm, 손가락 간섭).
- 걸리면 다른 종류로 바뀌기 쉽다. 그 결과 1개 장면이 늘어난다.

고친 코드(발췌)는 다음과 같다. 다시 뽑을 때는 처음 뽑은 장면 종류를 그대로 두고, 위치와 로봇 이동 값만 새로 뽑는다.

```python
lay_fix = None  # mix3 --keep-kind-on-relayout: 시도 처음에 뽑은 장면 종류
for _try in range(30):
    lay = sample_layout(fi)
    if args.keep_kind_on_relayout:
        if lay_fix is None:
            lay_fix = {"kind": lay["kind"], "count": lay["count"], "extra": dict(lay["extra"]),
                       "robot_on": tuple(lay["robot"]) != (0.0, 0.0, 0.0)}
        else:
            lay["kind"], lay["count"], lay["extra"] = lay_fix["kind"], lay_fix["count"], dict(lay_fix["extra"])
            ...  # 로봇 이동 여부도 고정(값만 새로), 1개 장면 종류(무작위/±8cm)도 고정
```

## 3. 왜 이렇게 판단했나

- **깊게 닫기가 원인이다.** V1 만 무너졌고 V2 는 v3 수준이다. 1판은 두 가지를 다 넣어서 0% 가 됐다.
- **힘 상한 계산이 틀렸던 이유** [추론]: 보고서 03 은 "힘 상한 1.0 N·m 라서 깊게 닫아도 쥐는 힘은 같다"고 봤다. 실제로는 다음과 같은 일이 생겼다.
  - 명령이 접촉보다 15~22단위 깊으면, 닫는 동안 계속 최대 힘으로 손가락이 돈다.
  - 회전식 손가락이 둥글거나 끝이 좁은 과일(딸기)을 적도 아래에서 누르면 위로 밀어내는 힘이 생긴다. 그래서 과일이 짜여 나간다.
  - 손끝 오차가 커진 것(4 → 14~19mm)은, 팔 강성이 낮아서(17.8) 그 반작용에 팔이 밀린 것으로 보인다.
  - 이것은 P0-d(실행할 때 정책의 그리퍼 값을 깊게 바꿈 → 0 대 3 으로 나빠짐)와 같은 방향이다. **이 시뮬레이터에서는 깊게 닫는 쪽이 일관되게 해롭다.**
- **가운데 맞춤을 남긴 이유**: 정책의 위치 오차를 버티게 하려는 것이다.
  - v3 는 고정 손가락이 과일에서 5mm 떨어져 내려간다. 정책이 그쪽으로 5mm 넘게 틀리면 고정 손가락이 과일을 누른다.
  - 2판은 여유가 8~11mm 다. 시연 성공률은 v3 와 같은 수준이다(V2 잡기 실패는 1/32).

## 5. 결론 및 추후 시사점

1. **잡기 값 확정**: v3 의 쥐는 깊이와 시간 + 가운데 맞춤. "깊게 쥐기로 오차를 버틴다"는 가설(H2 의 데이터 쪽 해법)은 이 시뮬레이터에서 성립하지 않는다.
2. **P4 '빠른 다시 잡기' 설계 전제가 깨졌다.** 5-3 은 "빈손(8~15)과 쥠(19~38)을 그리퍼 값으로 구분"하는 것을 전제로 했다. 그런데 v3 깊이에서는 빈손 값과 쥔 값의 차이가 약 3~4단위뿐이다.
   - 다시 잡기 데이터를 만들려면 손목 화면 단서에 기대야 한다.
   - P3 te −0.05 결과(다시 잡기가 살아나는지)를 보고 P4 를 할지 정한다.
3. **중간 깊이(접촉보다 6~8단위)는 시험하지 않았다.** 시간이 남으면 B 전에 딸기·오렌지 8회씩으로 확인할 수 있다. 다만 B 를 늦추면서까지 할 가치는 낮다고 본다(V1 이 크게 무너졌다).
4. **A 구성 확인**: 딸기 30회가 쌓이면 `mix3_stats.py` 로 여러 개 장면 비율을 다시 본다(아래 6장에 덧붙임).
5. 일정은 계획(A 09:30 시작)보다 빠르다. A 예상 종료는 약 13:30~14:00 이다. 이어서 P3 선별(약 40분)과 B 가 자동으로 시작한다.
