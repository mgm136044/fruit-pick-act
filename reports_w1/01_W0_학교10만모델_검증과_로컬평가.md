GPU 대기 스크립트에서 고친 부분(`after_gpu_free.sh`):

```bash
gpu_free() {   # 계산 프로세스 없음(원격 데스크톱 제외) + 1GB 미만 + ~/jobs 대기열 없음
  used=$(nvidia-smi --query-gpu=memory.used --format=csv,noheader,nounits | head -1)
  apps=$(nvidia-smi --query-compute-apps=process_name --format=csv,noheader | grep -v gnome-remote-desktop | grep -c .)
  [ "$used" -lt 1000 ] && [ "$apps" -eq 0 ] && ! pgrep -f "^/bin/bash $HOME/jobs/[^ ]*/run.sh" >/dev/null
}
```

## 5. 결론 및 추후 시사점

- **제출해도 되는 파일이다.** 사용자가 이 가중치로 서버에 낸 결과: n100 37.5 · n30 45.8 · n20 50.0 · te 0.01 **54.2**.
- **n100에서는 4만과 10만이 같다**(기본 7/24 대 8/24, 변형 30.0 대 32.5, 4개 장면 4/16 대 5/16). 학습 데이터 오차는 절반이 됐는데 실제 성적은 그대로다.
  - n100(3.3초 눈 감고 실행)에서는 학습량이 병목이 아니다.
  - 서버에서는 실행 설정만 바꿔 37.5 → 54.2 가 됐다.
- **남은 병목은 잡기와 들기다.** 실패 34회 중 23회가 '못 들어올림', 11회가 '들었다 놓침·접시 밖'이다. 딸기가 가장 약하다(기본 0/6, 4개 0/4).
- **조명 장면 0/8**(4만 4/8)은 색 증강 탓일 수 있다. 8회라 결론은 못 낸다(p≈0.08). P0-c에서 다시 본다.
- **운영 문제 1건**: 대기 스크립트가 마지막 확인 뒤 60초를 더 쉬고 다시 확인하지 않고 시작했다. 그 사이 시작된 다른 프로젝트 평가와 2분간 GPU를 같이 썼고, 그 평가는 중지됐다. 다음 대기 스크립트는 마지막 확인 직후 바로 시작하게 만든다.
