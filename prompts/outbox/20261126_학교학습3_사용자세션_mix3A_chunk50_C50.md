# 작업 (학교 GPU 세션, 처음 보는 에이전트용): 새 데이터 mix3 A 로 ACT 10만 스텝 학습 (변형 C50, chunk 50)

## 배경
- 수업 과제: Isaac Sim 과일 집기(SO-101 로봇) ACT 정책을 학습해 평가 서버에 낸다. **평가 서버 제출은 하지 않는다**(사람이 직접 한다).
- 지금 가장 좋은 모델은 mix2 데이터(589 에피소드)로 10만 스텝 학습한 것이다. 서버 54.2 점, 설정은 chunk 100, 색 증강만, temporal ensemble 0.01 이다.
- 새 데이터 `fruit_mix3_A` 는 스크립트 자동 시연이다(사람 시연 아님). 약 550 에피소드이고 다음을 바꿨다.
  - 과일을 두 손가락 가운데로 잡는다.
  - 같은 과일 2~4개 장면이 약 55% 다. 가장 가까운 것을 집는다.
  - 접시 이동, 로봇 이동, 과일 위치·회전을 넓혔다.
  - 다른 종류 과일 장면은 0% 다.
- 이 학습은 **변형 C50**: 변형 C(같은 데이터, chunk 100, 다른 세션에서 학습)와 **chunk_size 만 50 으로 다르다.** 나중에 DAgger 데이터를 더해 이어 학습한다(변형 B).
  - 이유: 제출 설정 temporal ensemble 은 겹치는 예측을 평균해 '놓친 뒤 다시 잡기' 전환을 늦춘다. chunk 50 이면 그 지연이 절반이다.
- 데이터는 이미 올라가 있다: 에피소드·프레임 551 · 162859, `fruit_mix3_A.zip` 3482271607 bytes, sha256 `61187afb44223c4f3537cbc782f8321a89273e9664e8cf17d690be30146b851a`.

## 2. 학습
```bash
cd /home/work/act_mix3_c50
nohup bash train.sh --data fruit_mix3_A.zip --steps 100000 --batch-size 16 --save-freq 10000 --name act_mix3A_c50_100k \
  --extra --policy.chunk_size=50 --policy.n_action_steps=50 --dataset.image_transforms.enable=true \
  --dataset.image_transforms.tfs='{"brightness": {"weight": 1.0, "type": "ColorJitter", "kwargs": {"brightness": [0.8, 1.2]}}, "contrast": {"weight": 1.0, "type": "ColorJitter", "kwargs": {"contrast": [0.8, 1.2]}}, "saturation": {"weight": 1.0, "type": "ColorJitter", "kwargs": {"saturation": [0.5, 1.5]}}, "hue": {"weight": 1.0, "type": "ColorJitter", "kwargs": {"hue": [-0.05, 0.05]}}}' \
  > train_c50.out 2>&1 &
```
- `--augment` 는 쓰지 않는다. 쓰면 선명도·위치 이동 증강까지 켜진다.
- **시작 1~2분 뒤 설정 출력을 확인한다.** 다르면 멈추고 outputs 를 지운 뒤 다시 시작한다.
  - chunk_size 50, n_action_steps 50
  - `image_transforms.enable: true`
  - tfs 네 개만(brightness·contrast·saturation·hue)
  - seed 1000, batch 16
- 첫 저장(1만) 뒤 `checkpoints/010000/pretrained_model/train_config.json` 으로 다시 확인한다.
- `outputs/act_mix3A_c50_100k` 의 저장 지점(`training_state` 포함)은 지우지 않는다. 나중에 이어 학습할 수 있다.

## 2-1. 자동 마무리 띄우기 (학습을 띄우고 설정을 확인한 직후)
학습이 끝나면 아래 zip·형식 검사·업로드를 대신 하는 스크립트를 nohup 으로 띄운다. 에이전트가 학습이 끝날 때까지 깨어 있지 않아도 올라간다.
```bash
cd /home/work/act_mix3_c50
huggingface-cli download mgm136044/fruit_mix3_train tools/auto_finish_upload.py --repo-type dataset --local-dir . && cp tools/auto_finish_upload.py .
sha256sum auto_finish_upload.py   # 08fe1f748235d5faeb36b18464a5dff941ed5ffb755c999478effc7d740dd33e  (다르면 실행하지 말고 보고)
PY=$(grep -o '학습 시작 · .*' train.log | tail -1 | sed 's/^학습 시작 · //'); "$PY" -c "import lerobot, huggingface_hub; print('ok')"
nohup "$PY" auto_finish_upload.py --name act_mix3A_c50_100k --repo mgm136044/act_mix3 \
  --zips 100000:plain:submission_act_mix3A_c50_100k,100000:te:submission_act_mix3A_c50_100k_te,80000:te:submission_act_mix3A_c50_80k_te,60000:te:submission_act_mix3A_c50_60k_te \
  --note "fruit_mix3_A (551ep · 162859프레임, 스크립트 자동 시연, 사람 시연 아님) · chunk 50 · 색 증강 4종" > auto_finish_act_mix3A_c50_100k.log 2>&1 &
sleep 30; cat auto_finish_act_mix3A_c50_100k.log
```
- 확인할 줄: `HF 확인 … (비공개)`, `학습 프로세스 감지: [pid …]`.
- `✘ HF 로그인 안 됨` 이면 사람에게 토큰을 요청한다. 사람이 토큰을 넣은 같은 셸에서 다시 띄운다.
- 학습이 끝나고 몇 분 뒤 로그 마지막 줄이 `AUTO_UPLOAD_DONE` 이면 성공이다. 스크립트는 저장소에 README 가 이미 있으면 받아서 이 학습의 절만 덧붙인다.
- **다음 zip 단계는 스크립트가 한다. 스크립트가 `✘` 로 끝났을 때만 직접 한다**(같은 파일을 두 번 올리지 않기 위해).

## 3. zip 만들기 — 스크립트가 하는 일(✘ 일 때만 직접)
- `pretrained_model` 안의 파일들을 zip 맨 위에 넣는다.
- 10만: `submission_act_mix3A_c50_100k.zip`(config 그대로, n_action_steps 50), `submission_act_mix3A_c50_100k_te.zip`
- 6만·8만: `submission_act_mix3A_c50_60k_te.zip`, `submission_act_mix3A_c50_80k_te.zip`
- `_te` 는 사본 config.json 의 `"n_action_steps": 1`, `"temporal_ensemble_coeff": 0.01` 두 값만 바꾼 것이다.
- 형식 검사: LeRobot 로 불러 무작위 입력(front·wrist 480x640x3, state 6)으로 `select_action` 을 120번 부른다. 숫자 6개, NaN 없음.
- sha256 을 적는다.
- `mgm136044/act_mix3`(비공개)에 zip 4개와 README.md 를 올린다.
  - **다른 세션(변형 C, chunk 100)도 같은 저장소에 올린다.** README.md 가 이미 있으면 먼저 받아서 내 줄만 더해 올린다. 다른 학습의 줄을 지우거나 덮어쓰지 않는다. zip 이름이 겹치지 않는지도 확인한다.
  - README 에 적을 것:
  - 데이터(저장소·zip 이름·에피소드·프레임 수, 사람 시연 아님)
  - 학습 설정
  - 파일 표(이름·스텝·실행 설정·sha256)
